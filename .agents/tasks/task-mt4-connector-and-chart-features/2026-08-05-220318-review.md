## Disconnect leaves stale persisted accountId

`Mt4RepositoryImpl.connect()` now correctly reads `appPreferences.getMetaApiAccountId()` and skips deploy when a value exists:

```kotlin
val cachedId = appPreferences.getMetaApiAccountId()
val deployedId = if (!cachedId.isNullOrBlank()) {
    cachedId
} else {
    val newId = dataSource.deployAccount(token, credentials)
    appPreferences.setMetaApiAccountId(newId)
    newId
}
```

However, `disconnect()` only clears the runtime field:

```kotlin
override suspend fun disconnect() {
    quoteStream.disconnect()
    accountId = ""
}
```

If a user disconnects (e.g., switching brokers or servers), the stale accountId remains in EncryptedSharedPreferences. On the next `connect()` call with different credentials, the code reuses the old account ID — the MetaApi REST calls will either fail (wrong account for new credentials) or succeed against the wrong account. The fix is straightforward: add `appPreferences.setMetaApiAccountId(null)` inside `disconnect()`.

## Bar-mode transforms lack test coverage

The test tree contains 90+ test files but no `HeikinAshiTransformerTest` or `CandleRenkoBuilderTest`. Both classes are `@Singleton` + `@Inject constructor()` with no dependencies — ideal for unit testing:

- `HeikinAshiTransformer.transform()` has a well-defined HA formula: verify the first bar uses standard open, subsequent bars average prior HA open/close, high/low respect the HA values.
- `CandleRenkoBuilder.build()` edge cases worth covering: empty input, single candle insufficient for one brick, multiple bricks from a single large candle, bearish bricks, and brick size zero/negative guard.

Both should follow the project's real-assert pattern (no mocks, compute expected values by hand and assert).
