# MT4 connector, bar-mode transforms, strategy overlays, and signal history

This change adds four interconnected features to the FoxTrader chart app: a full MetaApi-based MT4 connector (REST + WebSocket), a bar-mode selector that applies Heikin-Ashi and Renko transforms before indicator computation, strategy-as-indicator toggles that project LIT X and SMT analysis onto the chart canvas, and a unified signal overlay with live/history opacity differentiation. The implementation spans 33 new/modified files across the data, domain, DI, and feature layers, following the existing Hilt + MVVM + Compose architecture closely.

Watch for: SMT divergence detection is wired but will never produce results because `correlatedCandles` is always passed as `emptyMap()` (confirmed). The MetaApi auth token is embedded in the WebSocket URL as a query parameter, making it visible in server logs, proxy logs, and potentially crash reports (confirmed). No unit tests exist for HeikinAshiTransformer, CandleRenkoBuilder, or the signal computation pipeline (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The MT4 connector follows the project's established two-layer pattern (Retrofit service + DataSource adapter + repository impl), adds secure token storage via EncryptedSharedPreferences, and exposes a separate `Mt4QuoteStream` WebSocket for live quotes. The DI module creates its own OkHttpClient and Retrofit instance qualified with `@MetaApiRetrofit`, matching the existing per-provider isolation. The auth token is placed directly in the WebSocket URL's query string rather than a header, which is standard for MetaApi's real API contract but creates a credential-leakage surface in any intermediate logging.

The bar-mode feature cleanly inserts into the chart pipeline: transforms are applied after candle loading but before indicator computation, and SMC overlays that depend on temporal bar indices are correctly gated off when `preservesTimeAxis` is false. The Renko builder uses a straightforward brick-at-a-time algorithm that can produce an empty output if `brickSize` exceeds the total price range — the pipeline handles this with an early return.

Strategy-as-indicator toggles (LIT X, SMT, TradePro) are wired at the ViewModel level and drawn through a new `ChartSignalLayer`. However, the SMT detector's `correlatedCandles` parameter is hardcoded to `emptyMap()`, which triggers an early-return inside the detector, making the SMT toggle a no-op in its current state.

The unified signal model (`ChartSignal`) and the `ChartSignalHistory` composable give a consistent overlay regardless of signal source. Live signals render at 0.9 alpha, history at 0.3 — the differentiation is clear. The `SignalMarkerLabelPaint` in `ChartSignalLayer` mutates a shared `Paint` object's alpha on every call, which is a thread-safety concern given that `DrawScope` may be invoked from different frames or recomposition threads.

<summary>Issues (6)</summary>

1. **SMT divergence always empty** — `smtDivergenceDetector.detect()` is called with `emptyMap()` for `correlatedCandles`. The detector early-returns when this map is empty, so the SMT toggle never produces visible divergences. Pass actual correlated-pair candles (e.g., EURUSD ↔ DXY) or remove the toggle until the data pipeline is connected.
2. **Auth token in WebSocket URL** — `Mt4QuoteStream` puts the MetaApi token in a query parameter (`?auth-token=$authToken`). This leaks into OkHttp's internal logging, any proxy/CDN access logs, and Android's `StrictMode` network logging. If MetaApi supports header-based auth for WebSocket upgrades, use that instead; if not, ensure the OkHttp logging interceptor explicitly redacts the URL.
3. **Shared Paint mutation in DrawScope** — `SignalMarkerLabelPaint` is a top-level `val` whose `.alpha` is mutated inside `drawSignalMarkers`. If Compose ever invokes this from multiple threads (e.g., concurrent draw passes on different canvases), the mutation races. Use a per-call copy or pass alpha through `nativeCanvas.drawText` parameters.
4. **No tests for bar-mode transforms** — `HeikinAshiTransformer` and `CandleRenkoBuilder` are pure functions with well-defined expected outputs but have zero test coverage. Add unit tests following the `FakeXxxApi` / real-assert pattern.
5. **No tests for signal computation** — `computeSignals()` in `ChartViewModel` is private and tested only implicitly through the full state pipeline. Extract it into a testable utility and add coverage for edge cases (null analyses, empty divergence lists, multiple SMT entries).
6. **Mt4RepositoryImpl.connect deploys on every call** — Each `connect()` invocation calls `deployAccount()`, which provisions a new MetaApi cloud account. If the user disconnects and reconnects (or the app restarts), this creates duplicate cloud accounts. Consider persisting the accountId and calling deploy only when no ID exists.

## SMT divergence pipeline is dead-wired

In `ChartViewModel.processCandles`, the SMT detector is invoked as:

```kotlin
smtDivergenceDetector.detect(symbol, displayCandles, emptyMap())
```

The `SmtDivergenceDetector.detect` implementation checks `correlatedCandles.isEmpty()` as the second line and returns `emptyList()` when true. The entire SMT detection path — including the toggle in `IndicatorPanel`, the state field in `ChartUiState`, and the `drawSmtDivergences` layer — is assembled but inert. For this feature to function, the ViewModel needs to supply correlated-pair candle data (e.g., fetched from the repository for a peer symbol like DXY or GBPUSD depending on the primary symbol).

## Auth token exposure in WebSocket URL

`Mt4QuoteStream` constructs the WebSocket connection URL by embedding the MetaApi token directly:

```kotlin
val url = "$BASE_WS_URL?auth-token=$authToken&accountId=$accountId"
```

MetaApi's real streaming API does require this pattern, so the code correctly follows the vendor contract. The concern is operational: OkHttp's `HttpLoggingInterceptor` (configured at `BASIC` level in debug builds via `Mt4Module`) logs request URLs including query parameters. If the `@PublicMarketDataClient` OkHttpClient happens to share a logging interceptor, the token will appear in logcat. Android's `NetworkSecurityConfig` / `StrictMode` violations also surface full URLs. Mitigation: attach a redacting interceptor or explicitly verify that the `@PublicMarketDataClient` OkHttp instance used by this WebSocket has no logging interceptor that captures URLs.

## Shared mutable Paint in ChartSignalLayer

```kotlin
private val SignalMarkerLabelPaint = Paint().apply { ... }
// inside drawSignalMarkers:
SignalMarkerLabelPaint.apply { this.alpha = (alpha * 255).toInt() }
```

This top-level `Paint` object's alpha is mutated inside the draw loop. In the current single-chart architecture this works because only one Canvas draws at a time. But `MultiChartSection` renders multiple chart panels — if they ever share this layer code concurrently (or if Compose switches to parallel composition), the interleaved alpha writes will produce flickering markers. A defensive fix: create the paint once per `drawSignalMarkers` call or pass the alpha directly to `drawText`'s paint parameter without mutating the shared instance.

## Mt4RepositoryImpl always re-deploys accounts

`connect()` unconditionally calls `dataSource.deployAccount(...)`, which hits MetaApi's `POST /users/current/accounts` endpoint. According to MetaApi's API semantics, this creates a new cloud account each time. There is no check for whether an account with the same login/server already exists, and no accountId is persisted across app sessions. If a user connects, kills the app, and reconnects, a duplicate cloud account is created. The fix is to persist the MetaApi accountId (e.g., in EncryptedSharedPreferences alongside the token) and skip deploy when it's already known, falling back to deploy only on first connect or after explicit removal.

## Test coverage gaps

The `MetaApiDataSourceTest` is solid: it follows the `FakeXxxApi` pattern, asserts real computed values, and covers the happy path and error path for deploy/account-info/positions/trade. However, several other new components lack any test:

- `HeikinAshiTransformer` — a pure function with deterministic output that's trivially testable.
- `CandleRenkoBuilder` — similarly pure, and has edge cases worth covering (brick size larger than range, empty input, multiple bricks per candle).
- `computeSignals()` — private but extractable; the signal merging logic for multiple sources and the `isLive` marking have edge-case behavior.
- `Mt4QuoteStream` message parsing — the `parseAndEmit` function silently swallows malformed messages, which is correct behavior, but a test would verify the happy-path parsing contract.

## Renko edge case: empty output with large brick size

`CandleRenkoBuilder.build` returns an empty list if no candle's close exceeds `basePrice + brickSize`. The `processCandles` pipeline already handles this with `if (displayCandles.isEmpty()) return`, so it won't crash. But it means a user who sets a brick size too large (e.g., 100 pips on a pair that moved 50 in the visible window) sees a blank chart with no feedback explaining why. The UI doesn't surface this condition distinctly from "loading" or "no data".
