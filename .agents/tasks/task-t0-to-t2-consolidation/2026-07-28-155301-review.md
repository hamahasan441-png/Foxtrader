# Dead-code removal, ChartViewModel decomposition, and SMC compute reuse

This change consolidates the FoxTrader codebase across three vectors: it removes 35 orphaned real-time market engine files (19 production + 16 test, ~3,200 LOC), decomposes the 1,388-line `ChartViewModel` god-object into five focused controllers (reducing it to ~399 LOC of thin orchestration), and adds a compute-reuse path to `SmcDetector` with a bucket-based `findPriceClusters` replacing the previous O(n*k) scan. A minor housekeeping commit adds the Room schema output directory, a vector notification icon, and closes TODO comments. Net: -4,423 lines deleted, +1,898 added.

**Watch for:** The AI coordinator's `onResult` callback executes on a coroutine launched from `viewModelScope`, which means it fires on `Dispatchers.Main`—but there is no explicit dispatcher guarantee documented, and `runAiDecision` doesn't return a `Job`, so cancellation of in-flight AI work during rapid symbol changes relies entirely on the stale-check guard (**likely** race window). The bucket-based `findPriceClusters` uses `roundToLong` for bucket assignment, which changes behavior at tolerance boundaries vs. the old linear scan (**confirmed** behavioral difference, mitigated by equivalence tests passing). The `ChartMultiChartController` exposes its `_multiChartState` as a public `MutableStateFlow` rather than through a read-only `StateFlow` property (**confirmed** encapsulation leak).

## High-level view

The orphaned `data/market/*` engine had no Hilt module, no repository binding, no ViewModel reference. The diff is pure file removal with no collateral edits.

The ViewModel decomposition splits concerns into `ChartDataController` (market observation, prepend paging), `ChartIndicatorCoordinator` (indicator computation with incremental-update support), `ChartAiCoordinator` (multi-agent pipeline with fingerprint dedup), `ChartMultiChartController` (multi-panel layout and crosshair sync), and `ChartDrawingController` (drawing tool state machine). These are plain Kotlin classes—not Hilt-injected—which keeps the DI graph unchanged. The tradeoff: the ViewModel still injects 17+ dependencies and hands them off; the constructor hasn't gotten smaller, only the body.

The SMC refactor introduces `analyzeAll` as a single entry point that computes order blocks and FVGs once, then passes them to dependent detections (breakers, IFVGs, BPRs). `ComputeIndicatorsUseCase` gates on `toggles.orderBlocks && toggles.fairValueGaps` to decide whether to use the fused path—meaning the reuse benefit is only realized when both toggles are active. The `findPriceClusters` rewrite replaces O(n*k) cluster matching with O(n) bucket-hashing, which changes the clustering semantics subtly (fixed-width buckets vs. first-match radius).

<details>
<summary>Issues (5)</summary>

1. **MutableStateFlow encapsulation in ChartMultiChartController** — `_multiChartState` is accessed as a public `val` from the ViewModel. Expose it through a read-only `StateFlow` property to prevent external mutation.
2. **AI coordinator race on rapid symbol change** — Between the stale-check (`symbolFlow() != symbol`) and the `onResult` callback, there is a window where the symbol changes after the check passes but before the state is written. Guard by comparing again at write-time or use a monotonic sequence number.
3. **No cancellation handle for in-flight AI work** — `runAiDecision` launches a fire-and-forget coroutine; when the user switches symbols, the old coroutine runs to completion (wasting CPU) before the stale-check drops the result. Return and cancel the `Job` on context change.
4. **Bucket-based clustering boundary semantics** — The old `findPriceClusters` used first-match radius; the new version uses fixed-width buckets with adjacent-bucket merging. Prices within tolerance of each other but falling into non-adjacent buckets (>1 apart) will not cluster. Document this constraint.
5. **`ComputeIndicatorsUseCase` partial gating on `analyzeAll`** — The fused path activates only when both OB+FVG toggles are true. If only OBs are on, breakers still redundantly re-compute OBs internally. Consider always passing precomputed OBs when available.

## ChartMultiChartController state encapsulation

`ChartMultiChartController` declares:

```kotlin
val _multiChartState = MutableStateFlow(MultiChartUiState())
```

The ViewModel accesses it directly:

```kotlin
val multiChartState: StateFlow<MultiChartUiState> get() = multiChartController._multiChartState
```

This leaks mutation capability to anything with a reference to the controller. The conventional pattern is `private val _state` + `val state: StateFlow = _state.asStateFlow()`. The controller is `internal` and only the ViewModel holds it, limiting blast radius, but it should be tightened to prevent future misuse.

## AI coordinator concurrency model

`ChartAiCoordinator.runAiDecision` launches a coroutine on the provided `scope` (viewModelScope) but does not return the `Job`. The stale-check inside the coroutine:

```kotlin
if (symbolFlow() != symbol || timeframeFlow() != timeframe) return@launch
```

guards against delivering results for the wrong context, but the expensive `orchestrator.analyze` + `decisionEngine.evaluate` work still completes before being discarded. On rapid symbol switches (e.g., user scrolling through a watchlist), multiple AI pipelines run concurrently—the fingerprint guard (`lastAiCandlesHash`) doesn't prevent this because each new symbol resets the hash to 0.

The fix is to store the launched `Job` and cancel it in `resetCooldowns()` or at the top of `runAiDecision` before launching a new one. Results are correctly discarded (fail-safe), but unnecessary work burns CPU and battery on mobile.

## Bucket-based `findPriceClusters` semantics

The rewrite assigns each price to `bucket = (price / tolerance).roundToLong()` and merges adjacent buckets. The old algorithm scanned clusters linearly and matched `abs(clusterPrice - price) <= tolerance`. The behavioral difference:

- Old: a cluster's center drifts as new members join (first price wins as center), and prices are matched against the first cluster found.
- New: bucket centers are fixed at `k * tolerance` boundaries. Two prices 1.5*tolerance apart will never cluster (they fall in buckets more than 1 apart), whereas in the old algorithm the second price might have matched a cluster whose center drifted toward it.

The equivalence tests pass against real candle patterns, providing strong evidence the difference is not material for production data. But edge cases with exact-boundary synthetic prices could diverge. A comment documenting the "within 1 bucket" constraint would make the contract explicit.

## Test coverage gaps

Not tested: `ChartDataController` (market observation, prepend-merge logic, error paths), `ChartDrawingController` (drawing state machine), `ChartMultiChartController` (panel lifecycle, crosshair sync). The data controller's prepend-merge logic and error handling paths would benefit from unit tests in a follow-up—particularly the deduplication in `loadOlderHistory` and the `ConcatenatedCandleList` boundary behavior.
